# Piano: internazionalizzazione (i18n) dell’app web

Implementazione incrementale del supporto multilingua per `apps/web`, con **URL
localizzati** (`/{locale}/…`) per SEO e link condivisibili per lingua. Ogni punto
corrisponde a **una PR** suddivisa in **commit** atomici, con test e controlli CI
verdi prima del merge.

**Lingue supportate (v1):** inglese, francese, spagnolo, italiano, tedesco,
portoghese, cinese, giapponese.

## Requisiti di prodotto (vincolanti)

| Requisito | Specifica |
| --- | --- |
| Lingue | `en`, `fr`, `es`, `it`, `de`, `pt`, `zh`, `ja` |
| **URL localizzati** | Ogni pagina UI ha prefisso lingua: `/{locale}/…` (es. `/it/works`, `/fr/library`) |
| **Link condivisibili** | Condividere `/ja/works/42` apre la stessa pagina in giapponese per chiunque |
| **SEO** | `html lang`, `hreflang`, canonical per locale; redirect permanenti dai path legacy |
| Selettore lingua | Dropdown nel **menu principale** (header), bandierina + label nativa |
| Rilevamento automatico | Alla prima visita senza locale nel path, detect da `Accept-Language` / browser |
| Fallback | Lingua non supportata o detect impossibile → **`en`** (`/en/…`) |
| Persistenza | Cookie `andromeda_locale` allineato al locale dell’URL visitato (hint per redirect da `/`) |
| Catalogo traduzioni | File **JSON** in `apps/web/src/locales/*.json` |
| Rendering UI | Interpolazione chiavi → testo localizzato via `t()` / `useTranslation()` |
| Scope v1 | Tutte le stringhe UI in `apps/web`. Esclusi: metadata on-chain/IPFS, log server, messaggi server-only non mostrati in UI |
| Non obiettivo v1 | Traduzione manoscritti, RTL, plurali ICU avanzati, TMS esterno |

### Distinzione: lingua UI vs lingua opera

Il campo **Language** nel form publish (`work_imprint.language`) è la lingua
**letteraria** dell’opera (IPFS/OpenSea). La **lingua UI** è il segmento `/{locale}/`
e le chiavi JSON (`nav.*`, `catalog.*`, …). Restano concetti separati.

## Decisioni architetturali

### Modello: **locale nel path** (fonte di verità) + cookie (hint)

Il **segmento URL** `[locale]` è la fonte di verità per la lingua mostrata.
Il cookie `andromeda_locale` serve a:

1. Ricordare la preferenza quando l’utente visita `/` o un path **senza** prefisso.
2. Allinearsi all’URL dopo ogni navigazione localizzata.

**Non** si usa il solo cookie per cambiare lingua senza cambiare URL: il cambio
lingua dalla dropdown **naviga** a `/{newLocale}/stesso-percorso`.

```
Utente apre /works (legacy)
  → middleware: locale = cookie ?? Accept-Language ?? en
  → 308 → /it/works
  → set cookie andromeda_locale=it

Utente apre /fr/library (link condiviso)
  → middleware: valida fr, passa
  → set cookie andromeda_locale=fr
  → UI in francese (indipendente dal browser del destinatario)

Utente su /it/works/3 cambia lingua → Español
  → router.push(/es/works/3)
  → cookie=es
```

**Inglese con prefisso:** anche `en` ha path esplicito (`/en/works`), così ogni
lingua ha URL simmetrici e condivisibili. Non si usa il pattern “default locale
senza prefisso”.

### Middleware (`middleware.ts`)

Responsabilità:

| Caso | Azione |
| --- | --- |
| Path inizia con `/api`, `/_next`, file statici | `NextResponse.next()` |
| Path già valido `/{supportedLocale}/…` | `next()` + aggiorna cookie se diverso |
| Path senza prefisso (`/works`, `/library`, `/`) | Redirect **308** a `/{locale}{path}` |
| Prefisso non supportato (`/xx/works`) | Redirect 308 a `/en/…` (o 404 — scegliere 308 per UX) |
| Prima visita su `/` | `/{detectedLocale}` (cookie → `Accept-Language` → `en`) |

Matcher consigliato (escludere API):

```ts
export const config = {
  matcher: ["/((?!api|_next|.*\\..*).*)"],
};
```

Detect server-side: header `Accept-Language` (middleware); detect client-side
solo come fallback in dev. Il middleware è autoritativo per il primo redirect.

### Layer software

```
locales/*.json
    → lib/i18n (translate, interpolate, locales registry)
    → lib/i18n/routing.ts (localizedPath, stripLocale, switchLocale)
        → middleware.ts
        → app/[locale]/layout.tsx (params.locale)
            → I18nProvider(locale)
                → useTranslation() / LocalizedLink
                    → componenti UI
```

- **`lib/i18n/routing.ts`**: funzioni pure — `isSupportedLocale`, `localizedPath(locale, pathname)`,
  `switchLocaleInPath(pathname, newLocale)`, `stripLocalePrefix(pathname)`.
- **`LocalizedLink`**: wrapper di `next/link` che prepend il locale corrente.
- **`useLocale()`**: legge locale da `useParams().locale` (validato).

### SEO (v1)

Per ogni pagina indicizzabile:

1. **`html lang={locale}`** nel layout `[locale]`.
2. **`generateMetadata`** con:
   - `title` / `description` tradotti (chiavi `meta.*`).
   - `alternates.canonical`: URL assoluto con locale corrente.
   - `alternates.languages`: mappa hreflang → URL per tutte e 8 le lingue
     (es. `{ "it": "https://…/it/works", "en": "https://…/en/works", … }`).
3. **Redirect 308** da path legacy per trasferire ranking e evitare duplicati.
4. **`sitemap.xml`** (PR 9): entry per ogni pagina statica × 8 lingue; pagine
   dinamiche (opera, autore) con URL localizzati quando indicizzabili.

Pagine **noindex** (v1): `/admin/*`, flussi wallet-only se necessario.

## Strategia di migrazione

### Fase routing (prima delle stringhe)

1. Introdurre `[locale]` e middleware con redirect legacy.
2. Aggiornare **tutti** i link/redirect/router.push a path localizzati.
3. Verificare che l’app funzioni ancora in inglese (`/en/…`) con stringhe hardcoded.

### Fase traduzioni (dopo)

1. Estrarre stringhe in `en.json`.
2. Sostituire con `t()`.
3. Popolare gli altri 7 JSON.
4. Tradurre `generateMetadata` per pagina.

### Test

- Unit: `routing.ts`, detect, interpolate.
- Middleware: richieste simulate path con/senza locale.
- Componenti: `LocalizedLink` genera href corretto.
- Aggiornare test che assumono `/works` → usare `/en/works` o helper.

### generateMetadata (Server Component)


### Middleware (scheletro)

```ts
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";
import { detectLocaleFromHeader } from "@/lib/i18n/detect-locale";
import { DEFAULT_LOCALE, isSupportedLocale } from "@/lib/i18n/locales";
import { LOCALE_COOKIE, parseLocaleCookie } from "@/lib/i18n/cookie";

export function middleware(request: NextRequest) {
  const { pathname } = request.nextUrl;
  const segment = pathname.split("/")[1];

  if (isSupportedLocale(segment)) {
    const response = NextResponse.next();
    response.cookies.set(LOCALE_COOKIE, segment);
    return response;
  }

  const locale =
    parseLocaleCookie(request.cookies.get(LOCALE_COOKIE)?.value) ??
    detectLocaleFromHeader(request.headers.get("accept-language")) ??
    DEFAULT_LOCALE;

  const url = request.nextUrl.clone();
  url.pathname = `/${locale}${pathname === "/" ? "" : pathname}`;
  return NextResponse.redirect(url, 308);
}
```
